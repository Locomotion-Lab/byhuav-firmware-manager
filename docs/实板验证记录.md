# 实板验证记录

## macOS

测试时间：2026-10-29 至 2026-10-30。主机为 Apple Silicon，macOS 26.6.2（25G83）。测试工具为本地 0.1.2 修订版，使用随包的三份固件。

| 项目 | 结果 |
| --- | --- |
| ESP32、STM32 串口与约 32 GB 板卡 SD 识别 | 通过 |
| ESP32-S3 / 8 MB、安全设置与分区表检查 | 通过 |
| ESP32 完整 8 MB 原始备份及备份哈希 | 通过，备份保留在本机 |
| ESP32 应用写入、独立校验、OTA 选择区清理 | 通过 |
| ESP32 启动后的固件盘读回 | SHA-256 与交付镜像一致 |
| Core 暂存、复制校验、重启后文件处理 | 通过 |
| Core 网页验收 | 用户确认 2.0.0（95e901b4）、STM32 连接和传感器正常 |
| Bootloader 暂存、复制校验与安全卸载 | 通过 |
| Bootloader 重启、灯光与网页验收 | 用户确认灯光正常结束、STM32 连接与传感器正常；未读取 Bootloader 版本 |
| 最终检查与报告 | 更新目录为空，ESP32 固件盘哈希及原始备份完整性通过，已保存更新结果 |

测试中修正了以下电脑端问题：

- 从 USB 父设备继承序列号，使用 SCSI 厂商和产品识别实际磁盘，避免将复合 USB 产品名当作磁盘型号。
- 处理 esptool 使用退格符输出的备份进度。
- 将写入完成后的启动读回独立保存为一个阶段；核对完整成功记录后恢复，避免重复烧录。
- 对本次固件复制产生的 Mac AppleDouble 元数据先备份、再清理，保留其他未知文件。
- 明确两次重启可用“拔掉 U29 USB 后断电再上电”替代复位按钮。

Core 重启后的第一次 USB 重连曾出现 SD 读取错误，Mac 停用了存储接口；重新接牢 U29 USB 后，磁盘恢复且更新目录为空。该现象的内核日志保存在本机，尚未据此确定板卡固件或连接的根因。不要在未恢复磁盘时继续暂存 Bootloader。

旧 ESP32 镜像与交付镜像不同，但未读取到可靠的旧业务版本号，因此不能仅凭其 SDK 版本声称已经覆盖所有 1.x 固件版本。此次测试证明的是这块板卡上的实际迁移路径。

## Windows / Linux

待用户将板卡连接到对应主机后进行实板测试。跨平台离线测试通过不等于真实 USB、磁盘挂载和刷写验证。

同一块板卡完成本次升级后，后续先验证 Windows / Linux 的设备识别和磁盘流程。2.x 应用能否在对应主机上无按钮自动进入 ESP32 下载模式仍需单独验证；本次 Mac 恢复测试中，普通自动连接序列未成功进入下载模式，后续核对原成功记录与实际固件读回后继续，未重复烧录。

严格验证各系统从原始 1.x 开始的迁移，还需要保留有代表性的 1.x 板卡，不能将同一块已升级板卡的测试当作原始 1.x 迁移证据。
