# 维护与验证

## 范围与已知限制

- 外部 Windows 10/11、桌面 Linux、macOS 运行；不依赖机载 Jetson 操作系统。
- 基于 PlatformIO 已初始化的 Python 3.9+，单独建立烧录环境；固定 esptool 4.11.0、pyserial 3.5，不向 PlatformIO 环境安装这些依赖。
- SD 卡识别要求 USB 型号 `BYHUAV SD Flash Disk`、约 32 GB、稳定序列号及已存在的 `BYHUAV/FirmwareUpdate` 目录。
- ESP32 串口标识 `303A:1001`，STM32 串口标识 `0483:572A`。不同 USB 标识的旧板卡会停止，不能据此判定板卡故障。
- ESP32 必须是 S3 / 8 MB、未开启安全启动和 Flash 加密，且有兼容分区表。工具不执行整片擦除、不处理 eFuse、不提供工厂恢复。
- ESP32 写入 app0 `0x10000`；独立校验成功后才擦除 `0xe000` 开始的 `0x2000` 字节 OTA 选择区。
- STM32 应用限制 917,504 字节，Bootloader 限制 1,048,576 字节；分别检查向量入口范围。只使用随附且哈希一致的三个固件。
- Core、Bootloader 由 SD 文件触发，必须由用户安全弹出、断开 U29、重启并验收。工具不自动控制 Jetson GPIO，不猜测 STM32 重启命令。
- Core 成功依据包含人工网页验收；Bootloader 成功依据包含人工灯光、应用恢复验收，未读取 Bootloader 版本。文件消失不单独代表成功。
- 暂存使用唯一 `.pending` 文件、复制校验、改名与落盘。安全卸载仍由操作系统和用户完成。
- 会话绑定设备三项身份、完整 manifest 摘要及工具版本；更新中断后须使用原更新包继续。备份与日志独立于下载目录。
- 新任务只在上一任务完成后建立。没有自动回滚及备份恢复命令；异常设备应由维护人员处理。

## 固件来源

固件取自项目所有者提供的原 Windows 更新包；新工具没有重新编译或修改二进制内容。精确大小和 SHA-256 见根目录 `manifest.json`。`package_version` 是迁移包标识，不等于三个固件共有的构建版本。

未分发原来的机载 ros-web-ui deb、依赖包、旧 Windows 教程或参考 PDF。公开仓库只包含本次外部主机工具与必要固件。

## 本地验证

```bash
python3 -m unittest discover -s tests -v
python3 update.py --verify-package
python3 tools/build_release.py
```

上面三项不访问串口或板卡。不依赖真实板卡的测试使用模拟系统信息、临时磁盘目录和合成分区表。`--verify-package` 不安装依赖。

使用实际 PlatformIO 环境检查启动和依赖（仍不读取设备）：

```bash
bash update.sh --prepare
```

Windows 对应 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Update.ps1 --prepare`。

`--check` 只枚举串口和磁盘、校验固件，不打开串口、不写 SD、不建立更新会话。`--status` 只读取已有会话。

CI 覆盖 Ubuntu / macOS / Windows 与 Python 3.9 / 3.11，验证离线流程、固件、依赖及启动脚本。**CI 不能代替真实 USB 设备的识别、驱动、权限、安全卸载、串口时序与实际刷写验证。**

## 首板验证

批量发放前，每个支持的操作系统都应完成一块有代表性的 1.x 板卡迁移，保留日志：

1. 确认识别到两个串口、正确的 SD 卡和设备序列号；确认多板卡会停止。
2. 确认 ESP32 完整备份和实际分区布局兼容，备份可由维护人员另行校验。
3. 确认 ESP32 更新后固件盘会出现并可读回 `FIRMWARE.BIN`。
4. 完成 Core、Bootloader 两轮安全移除和物理重启；按教程验证网页及灯光。
5. 重连时串口、盘符或挂载点变化仍能匹配原设备。
6. 在只读检查和已完成备份等安全阶段测试退出、恢复；不要为了测试强行中断 Bootloader 擦写。

目前仓库不宣称已经完成上述实板验证。

## 发布

`tools/build_release.py` 使用明确的文件白名单构建 ZIP，并生成带固定包 SHA-256 的 `install.sh` / `Install.ps1`。输出在 `dist/`，不会包含原始交付、工作目录中的日志或备份。

源码合入并通过 CI 后，创建与 `byhuav_updater.VERSION` 对应的 Git tag，再将 ZIP、`SHA256SUMS` 和两个安装入口作为同一 GitHub Release 的资产上传。首次版本标记预发布，注明实板验证边界。教程固定指向版本，不使用漂移的 `latest`。

发布后验证公开下载和包哈希；无需连接板卡即可用下载入口运行 `--verify-package`。不要覆盖已发布版本的同名资产。换固件、工具或教程时发新版本。

如果以后镜像到 Gitee，使用完全相同的 ZIP 和哈希，并为镜像地址重新生成入口。工具下载可镜像，但首次 pip 依赖下载需要单独解决网络可达性。
