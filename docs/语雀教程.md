# BYHUAV 板卡：从 1.x 升级到 2.x

本教程在 **外部电脑** 上更新板卡的 ESP32、STM32 Core 和 Bootloader。Windows、Linux、macOS 使用同一套向导；Jetson 是否已经安装系统不影响此流程。

> 首次发布：请先由维护人员完成对应电脑系统的实板验证，再用于批量升级。遇到“停止”提示时保留现场和更新记录。

## 1. 准备好电脑和板卡

1. 电脑安装 [VS Code](https://code.visualstudio.com/)，在扩展中安装 **PlatformIO IDE**。打开一次 PlatformIO，等待初始化完成。首次使用需要联网。
2. 停止采集，拆除桨叶，为板卡接好独立、稳定的电源。拔掉电脑 USB 后，板卡仍需持续供电。
3. 每次只连接一块板卡。用能传输数据的 USB 线，将电脑连接到 **U29：下板 Type-C 维护口**。
4. 准备手机，后面用它连接 **ESP32 的 Wi-Fi** 查看更新结果。注意区分板载路由器 Wi-Fi。

本次目标：ESP32 **2.0.0（6e39ffb4）**，STM32 Core **2.0.0（95e901b4）**，以及更新包内的 Bootloader。

## 2. 复制一条命令，启动向导

根据电脑系统选择一条。命令会获取固定版本工具、校验更新包，并准备烧录环境。**后面按向导操作即可，无需再输入其他启动命令。**

### Windows

打开 **PowerShell**，粘贴并执行整行：

```powershell
$ErrorActionPreference='Stop'; $f=Join-Path $env:TEMP ('byhuav-'+[guid]::NewGuid()+'.ps1'); Invoke-WebRequest 'https://github.com/Locomotion-Lab/byhuav-firmware-manager/releases/download/v0.1.1/Install.ps1' -OutFile $f -UseBasicParsing; & powershell.exe -NoProfile -ExecutionPolicy Bypass -File $f
```

### macOS / Linux

打开 **终端**，粘贴并执行：

```bash
curl -fsSL https://github.com/Locomotion-Lab/byhuav-firmware-manager/releases/download/v0.1.1/install.sh | bash
```

### 如果下载失败

可在 [版本下载页](https://github.com/Locomotion-Lab/byhuav-firmware-manager/releases/tag/v0.1.1) 下载 `byhuav-firmware-manager-v0.1.1.zip`，**完整解压**，再打开解压后的文件夹：

- Windows：在文件资源管理器地址栏输入 `powershell` 并回车，执行 `.\update.cmd`。
- macOS / Linux：终端进入解压目录，执行 `bash update.sh`。可先输入 `cd `（末尾有空格），把解压文件夹拖入终端，再回车。

## 3. 跟着向导完成更新

向导会依次处理以下环节：

| 环节 | 你需要做什么 |
| --- | --- |
| 核对板卡 | 对照标签或 ESP32 热点名称，输入 MAC 后 4 位；确认迁移时输入 `UPDATE` |
| ESP32 备份和更新 | 保持电源、USB 连接，等待备份、烧录、校验完成 |
| Core 更新 | 按下面的“第一次重启”操作，验收后输入 `CORE-OK` |
| Bootloader 更新 | 提示时输入 `UPDATE-BOOT`，再按“第二次重启”操作，验收后输入 `BOOT-OK` |

### 第一次重启：更新 Core

向导提示 Core 已复制并校验后：

1. 在电脑系统中 **安全弹出板卡 SD 卡**。Windows 在资源管理器中弹出；macOS 在访达中弹出；Linux 在文件管理器中安全移除。操作失败时先关闭正在访问该盘的窗口，不要强行拔线。
2. 拔掉连接电脑的 U29 USB，再按设备流程 **重启 STM32 主控板**。
3. 保持稳定供电，**至少等待 15 秒**，期间不要插回 USB。
4. 用手机连接当前板卡的 ESP32 Wi-Fi，打开 **http://192.168.4.1/**。默认热点为 `esp32_byh_<MAC后4位>`，默认密码 `88888888`；已修改时使用实际名称和密码。“无互联网”时选择仍然连接。
5. 检查 **STM32 已连接**，MCU 版本为 **2.0.0（95e901b4）**，运行时间持续增加、传感器有数据。
6. 全部符合后，将 U29 USB 接回电脑，等待 SD 卡重新出现；若没有自动挂载，先用文件管理器打开它，再在向导中输入 `CORE-OK`。

### 第二次重启：更新 Bootloader

向导提示 Bootloader 已复制并校验后：

1. 再次 **安全弹出板卡 SD 卡 → 拔掉 U29 USB → 重启 STM32 主控板**。
2. 保持稳定供电，**至少等待 30 秒**，期间不要插回 USB。观察指示灯：

   **紫 → 红 → 蓝闪 → 绿闪 → 紫**

   **如果停在黄色：停止操作，联系维护人员。不要反复断电、重启或继续刷写。**

3. 灯光正常结束后，刷新手机网页，确认 STM32 恢复连接、传感器正常。MCU 显示的仍是 Core 版本，属于正常情况。
4. 将 U29 USB 接回电脑，等待 SD 卡出现并挂载，在向导中输入 `BOOT-OK`。

看到 **`[完成] 本次固件迁移验收完成`** 后，安全弹出 SD 卡、拔掉维护 USB，恢复板卡正常连接。

## 遇到问题怎么办

| 情况 | 处理方法 |
| --- | --- |
| 提示找不到 PlatformIO | 在 VS Code 中确认 PlatformIO IDE 已安装并完成初始化，再重新运行 |
| ESP32 一直显示 Connecting | 关闭串口监视器；按住 ESP32 BOOT → 点按 ESP32 RESET → 松开 BOOT，等待 USB 恢复后重新运行原命令 |
| 找不到 SD 卡或更新目录 | 检查 U29、数据线和 SD 卡；用文件管理器打开板卡 SD 卡。不要格式化或手工创建更新目录 |
| Linux 提示没有串口权限 | 见下方权限处理；不要使用 `sudo` 运行更新工具 |
| 关闭了窗口、更新中断 | 保持板卡供电，重新运行**同一版本命令或同一解压包**，输入 `CONTINUE` 恢复原进度。已经暂存固件时不要自行跳过重启与验收 |
| 不兼容、哈希失败、更新目录有未知文件 | 停止，保留报错和记录，联系维护人员；不要自行替换固件继续 |

Linux 串口权限：先按 [PlatformIO 官方说明](https://docs.platformio.org/en/latest/core/installation/udev-rules.html) 配置设备权限。Ubuntu 常见做法是将当前用户加入 `dialout` 组：

```bash
sudo usermod -aG dialout "$USER"
```

执行后**注销并重新登录**，重新连接板卡。其他发行版请按官方说明确认实际用户组。

## 保存更新结果

工具会显示记录目录，内含 ESP32 完整 Flash 备份、日志和 `更新结果.txt`。默认位置：

- Windows：用户文件夹下的 `.byhuav-firmware-manager\records`。
- macOS / Linux：`~/.byhuav-firmware-manager/records`。

请保留记录，完整 Flash 备份可能包含设备配置，不要公开上传。全部固件验收通过后，按独立教程完成系统镜像烧录（如需要），**最后完成设备注册**。后续 2.x 日常更新使用 Jetson Web 服务的对应教程。
